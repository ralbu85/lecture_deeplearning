어텐션과 Self-Attention

학습 목표
  • RNN의 두 가지 병목(순차 처리, 먼 기억 소실)이 왜 구조적 한계인지 설명할 수 있다
  • 어텐션이 “유사도 → Softmax → 가중평균”의 조합임을 이해하고, 각각이 어느 장에서 배운 도구인지 짚을 수 있다
  • Query, Key, Value의 역할을 검색 비유로 설명할 수 있다
  • 소형 Q·K·V가 주어졌을 때 어텐션 가중치와 새 표현 벡터를 직접 계산할 수 있다
  • Self-Attention이 단어의 표현을 “문맥을 반영한 표현”으로 바꾼다는 것을 예시로 설명할 수 있다
  • 인과 마스크가 왜 필요한지 설명하고, 마스크를 적용한 어텐션 가중치를 직접 계산할 수 있다
  • Multi-Head Attention의 분할–계산–결합 과정을 텐서 모양으로 추적하고, 파라미터 수를 계산할 수 있다

이 장은 이 수업 손계산 여정의 정점이다. 퍼셉트론(Ch02), 콘볼루션(Ch06), IoU(Ch09), 유사도(Ch10)를 거쳐 온 손계산이 여기서 하나로 합쳐진다 — 그리고 놀랍게도, 새로 배울 수학은 하나도 없다.

RNN의 병목 재확인

Ch10의 마지막 질문을 회수하자. RNN은 문장을 한 단어씩 순서대로 읽으며 hidden state라는 기억 상자에 지금까지의 내용을 눌러 담았다. 이 설계에는 두 가지 구조적 병목이 있었다:

  1. 순차 처리 — 병렬화 불가. \(t\)번째 단어를 처리하려면 \(t-1\)번째 계산이 끝나야 한다. 단어 1,000개짜리 문서는 1,000단계를 기다려야 한다. GPU가 수천 개의 연산을 동시에 할 수 있어도(Ch01), RNN은 그 능력을 쓸 수 없다.
  2. 먼 기억의 소실. 모든 과거를 고정 크기 벡터 하나에 눌러 담으니, 문장이 길어질수록 앞부분의 정보가 희미해진다. “Those dogs ate their food, … they were very happy”에서 they를 처리할 때쯤이면 dogs는 기억 저편이다.

두 병목의 뿌리는 같다 — “순서대로, 하나의 기억 상자를 거쳐서”라는 설계 자체다. 그렇다면 요구사항을 다시 정의해 보자:

모든 단어를 동시에 보되, 필요한 곳에 집중할 수 있어야 한다.

“동시에 본다”가 병렬화를 해결하고, “필요한 곳에 집중한다”가 먼 기억 문제를 해결한다 — 아무리 멀리 있는 단어라도 필요하면 직접 참조하면 되기 때문이다. 이 요구사항을 구현한 것이 어텐션(Attention)이다.

어텐션의 직관: 번역하는 사람의 시선

“나는 어제 학교에서 친구를 만났다”를 영어로 옮긴다고 하자. “I met a friend at school yesterday”에서 “met”을 쓰는 순간, 여러분의 시선은 원문의 어디에 가 있는가?

  • “만났다”를 가장 강하게 본다 — 동사 자체니까
  • “어제”도 곁눈질한다 — meet이 아니라 met(과거형)을 골라야 하니까
  • “학교에서”는 지금은 거의 안 본다 — at school은 다음에 쓸 것이다

즉 번역가는 출력 단어 하나를 만들 때마다 원문 전체를 서로 다른 강도로 참조한다. 어텐션은 정확히 이것을 수식으로 옮긴 것이다:

정의: 어텐션 (Attention)

지금 처리 중인 단어가 다른 단어들을 얼마나 참고할지의 가중치를 정하고, 그 가중치로 다른 단어들의 정보를 가중평균하는 연산.

\[\text{참고할 정도(유사도)} \;\xrightarrow{\text{Softmax}}\; \text{가중치(합=1)} \;\xrightarrow{\text{가중평균}}\; \text{새 표현}\]

여기서 강조할 것이 있다. 어텐션에는 새 수학이 없다.

단계 쓰는 도구 어디서 배웠나
참고할 정도를 잰다 벡터의 내적(유사도) Ch10
정도를 가중치로 바꾼다 Softmax (합이 1인 확률로) Ch03
정보를 합친다 가중평균 고등학교

이미 손에 익은 세 가지를 순서대로 이어 붙이면 어텐션이 완성된다. 이 장에서 할 일은 이 조립을 직접 계산으로 확인하는 것뿐이다.

Q·K·V: 세 가지 역할

가중평균까지 가려면 먼저 “누가 누구를 참고하는가”를 정리할 언어가 필요하다. 어텐션은 각 단어에 세 개의 벡터를 부여한다.

정의: Query, Key, Value
  • Query (Q) — 내가 지금 찾고 있는 것. “나에게 필요한 정보는 무엇인가?”
  • Key (K) — 각 단어가 내건 색인(간판). “나는 이런 정보를 갖고 있다”
  • Value (V) — 각 단어가 실제로 전달할 내용

Query와 Key의 내적이 크면 “찾는 것과 간판이 잘 맞는다” → 그 단어의 Value를 많이 가져온다.

도서관 검색에 비유하면 정확하다. 여러분이 검색창에 입력하는 검색어가 Query, 각 책의 제목·키워드가 Key, 책의 본문이 Value다. 검색 엔진은 검색어와 잘 맞는 제목의 책일수록 결과 상단에 올리고(가중치), 여러분은 그 책들의 내용을 읽는다(Value를 가져온다). 어텐션이 다른 점은 하나뿐이다 — 1등 하나만 고르는 대신, 모든 책을 가중치만큼 섞어 읽는다.

Q·K·V는 어디서 오는가? 각 단어의 임베딩 벡터(Ch10)에 학습되는 행렬 \(W_Q, W_K, W_V\)를 곱해서 만든다. 즉 “무엇을 찾고, 무엇을 간판으로 내걸고, 무엇을 전달할지”조차 데이터로부터 학습되는 파라미터다 — 경사하강법(Ch03)으로 갱신된다는 점은 지금까지의 모든 가중치와 같다. 이 장의 손계산에서는 차원 폭발을 막기 위해, 이 곱셈이 끝난 Q·K·V 값이 이미 주어진 상태에서 시작한다.

어텐션 손계산 — 이 장의 심장

토큰 3개짜리 문장 “고양이가 / 생선을 / 먹었다”로 single-head self-attention 1회를 끝까지 계산한다. 각 토큰의 Q·K·V는 차원 2로 다음과 같이 주어졌다고 하자.

코드 
import pandas as pd
import numpy as np

tokens = ['고양이가', '생선을', '먹었다']
Q = np.array([[2, 1], [1, 2], [1, 3]], dtype=float)
K = np.array([[1, 0], [0, 2], [1, 1]], dtype=float)
V = np.array([[1, 0], [0, 1], [1, 1]], dtype=float)

pd.DataFrame({
    '토큰': tokens,
    '$q$ (Query)': [f'({q[0]:.0f}, {q[1]:.0f})' for q in Q],
    '$k$ (Key)': [f'({k[0]:.0f}, {k[1]:.0f})' for k in K],
    '$v$ (Value)': [f'({v[0]:.0f}, {v[1]:.0f})' for v in V],
}).to_html(index=False, border=0, escape=False)

Value의 두 성분을 대략 (1번째 = “동물 성분”, 2번째 = “음식 성분”) 정도의 의미로 읽어 두면 마지막 결과가 눈에 들어올 것이다.

(a) 스코어: Q와 K의 내적

모든 (Query 토큰, Key 토큰) 쌍에 대해 내적을 계산한다. Ch10에서 한 그 내적 그대로다. 예를 들어 “먹었다”의 Query와 “생선을”의 Key라면:

\[q_{\text{먹었다}} \cdot k_{\text{생선을}} = (1, 3) \cdot (0, 2) = 1 \times 0 + 3 \times 2 = 6\]

9쌍을 전부 계산하면 \(3 \times 3\) 스코어 표가 나온다:

코드 
S = Q @ K.T   # 모든 쌍의 내적을 한 번에

df = pd.DataFrame(S, columns=[f'{t}의 $k$' for t in tokens])
df.insert(0, 'Query \\ Key', [f'**{t}의 $q$**' for t in tokens])
df.to_html(index=False, border=0, escape=False)

“먹었다” 행을 보라 — (1, 6, 4). 설계된 대로 “먹었다”의 Query는 “생선을”의 Key와 가장 잘 맞는다 (무엇을 먹었는지가 가장 필요한 정보다).

(b) √d로 나누기: 스케일링

스코어를 그대로 Softmax에 넣지 않고 차원의 제곱근 \(\sqrt{d}\)로 나눈다. 차원이 커지면 내적 값 자체가 커지고, 값이 커지면 Softmax가 한 곳에 확률을 몰아주는 극단적 분포가 되기 때문에 이를 완화하는 안전장치다. 여기서는 \(d = 2\)이므로 \(\sqrt{2} \approx 1.414\)로 나눈다. “먹었다” 행은 \((1, 6, 4) \rightarrow (0.71,\ 4.24,\ 2.83)\)이 된다.

(c) 행별 Softmax: 스코어를 가중치로

각 행(Query 토큰 하나)에 대해 Softmax를 적용한다. Ch03에서 배운 그 Softmax, 표기까지 그대로다:

\[\text{softmax}(z_k) = \frac{e^{z_k}}{\sum_{j=1}^{K} e^{z_j}}\]

Ch03에서는 \(z\)가 “클래스 점수”였고 지금은 “참고할 정도”라는 것만 다르다. “먹었다” 행을 Ch03의 수치 예시와 같은 형식으로 계산하면:

코드 
z = S[2] / np.sqrt(2)          # 먹었다 행의 스케일된 스코어
exp_z = [np.exp(zi) for zi in z]
sum_exp = sum(exp_z)
softmax = [e / sum_exp for e in exp_z]

rows = []
for k in range(3):
    rows.append({
        '참조 토큰': tokens[k],
        '스코어': f'{S[2][k]:.0f}',
        '$z_k = $ 스코어$/\\sqrt{{2}}$': f'{z[k]:.4f}',
        '$e^{{z_k}}$': f'{exp_z[k]:.4f}',
        '$\\text{{softmax}}(z_k)$': f'{softmax[k]:.4f}',
        '가중치 (%)': f'{softmax[k]*100:.1f}%',
    })

rows.append({
    '참조 토큰': '**합계**',
    '스코어': '',
    '$z_k = $ 스코어$/\\sqrt{{2}}$': '',
    '$e^{{z_k}}$': f'{sum_exp:.4f}',
    '$\\text{{softmax}}(z_k)$': f'{sum(softmax):.4f}',
    '가중치 (%)': '100.0%',
})

pd.DataFrame(rows).to_html(index=False, border=0, escape=False)

“먹었다”는 자신의 새 표현을 만들 때 “생선을”을 78.6%, 자기 자신을 19.1%, “고양이가”를 2.3% 참고하기로 결정했다. 같은 절차를 세 행 모두에 적용하면 어텐션 가중치 행렬이 완성된다 (각 행의 합 = 1):

Query \ Key 고양이가 생선을 먹었다
고양이가 0.248 0.248 0.503
생선을 0.074 0.620 0.306
먹었다 0.023 0.786 0.191

(d) 가중합: 새 표현 벡터

마지막 단계 — 가중치로 Value들을 가중평균한다. “먹었다”에 대해 끝까지 계산하면:

코드 
w = np.array(softmax)          # 먹었다 행의 가중치

rows = []
for k in range(3):
    wv = w[k] * V[k]
    rows.append({
        '참조 토큰': tokens[k],
        '가중치 $w_k$': f'{w[k]:.4f}',
        '$v_k$': f'({V[k][0]:.0f}, {V[k][1]:.0f})',
        '$w_k \\times v_k$': f'({wv[0]:.4f}, {wv[1]:.4f})',
    })

out = w @ V
rows.append({
    '참조 토큰': '**새 표현 (합)**',
    '가중치 $w_k$': '',
    '$v_k$': '',
    '$w_k \\times v_k$': f'**({out[0]:.4f}, {out[1]:.4f})**',
})

pd.DataFrame(rows).to_html(index=False, border=0, escape=False)

“먹었다”의 새 표현은 \((0.214,\ 0.977)\) — 2번째 성분(“음식 성분”)이 압도적이다. 어텐션 1회를 거치며 “먹었다”라는 단어의 벡터에 “생선을 먹었다”라는 문맥이 스며든 것이다. 이것이 어텐션이 하는 일의 전부다: 내적으로 재고, Softmax로 나누고, 가중평균으로 섞는다.

손으로 따라 해 보라: “고양이가” 행에 대해 (b)~(d)를 반복하면 새 표현 \((0.752,\ 0.752)\)가 나와야 한다. 문제집의 손계산 문제가 정확히 이 형태다.

인터랙티브 — 어텐션 가중치를 눈으로 확인하세요

번역 예시 문장 “나는 어제 학교에서 친구를 만났다”의 토큰 5개에 Q·K 값(차원 2)을 미리 넣어 두었어요. Query 토큰을 선택하면, 그 토큰의 Q와 모든 K의 스코어 → Softmax 가중치가 연결선의 굵기와 막대로 표시됩니다. “만났다”를 선택해 보세요 — 번역가의 시선처럼 “친구를”에 가장 집중하는 것을 볼 수 있어요.

viewof attnSel = Inputs.radio(["나는", "어제", "학교에서", "친구를", "만났다"], {

})
attnCalc = {

  const Q = [[1.5, 0.4], [-0.4, 1.6], [1.1, 1.0], [0.6, 1.7], [0.9, 2.3]];
  const K = [[1.4, 0.3], [-0.5, 1.5], [1.0, 1.0], [0.5, 1.7], [1.2, 0.9]];
  const i = tokens.indexOf(attnSel);
  const q = Q[i];
  const scores = K.map(k => q[0] * k[0] + q[1] * k[1]);
  const scaled = scores.map(s => s / Math.sqrt(2));
  const exps = scaled.map(s => Math.exp(s));
  const sum = exps.reduce((a, b) => a + b, 0);
  const weights = exps.map(e => e / sum);
  return { tokens, i, q, K, scores, scaled, weights };
}
{

  const n = c.tokens.length;

  const cx = j => xs[j] + boxW / 2;

      .attr("d", `M ${x1} ${y} Q ${(x1 + x2) / 2} ${y - lift}, ${x2} ${y}`)
      .attr("fill", "none")

      .attr("stroke-opacity", 0.3 + c.weights[j] * 0.7)
      .attr("stroke-linecap", "round");
  }

      .attr("fill", "none")

      .attr("stroke-width", 1 + c.weights[c.i] * 16)

  }

  // 토큰 상자 (배경 진하기 = 받는 가중치)
  for (let j = 0; j < n; j++) {

      .attr("fill-opacity", sel ? 0.9 : 0.12 + c.weights[j] * 0.8)
      .attr("stroke", sel ? "#1F3F7A" : "#8C1515")
      .attr("stroke-width", sel ? 2.5 : 1.2);
    svg.append("text")
      .attr("x", xs[j] + boxW / 2).attr("y", y + 22)
      .attr("text-anchor", "middle")
      .attr("font-size", "13").attr("font-weight", "700")
      .attr("fill", sel || c.weights[j] > 0.32 ? "white" : "#333")
      .text(c.tokens[j]);
    svg.append("text")
      .attr("x", xs[j] + boxW / 2).attr("y", y + boxH + 18)
      .attr("text-anchor", "middle")

  }

  svg.append("text")
    .attr("x", W / 2).attr("y", 18)

  return svg.node();
}

Self-Attention의 의미: 문맥을 입은 단어

위 계산에서 문장은 자기 자신을 참조했다 — Query도, Key도, Value도 같은 문장의 토큰들에서 나왔다. 그래서 Self-Attention이다. 그 결과가 무엇이었는지 다시 보자:

  • 어텐션 전: “먹었다”의 벡터는 어느 문장에 있든 똑같은, 사전에 박제된 표현
  • 어텐션 후: “먹었다”의 벡터는 “생선을”의 정보가 78.6% 섞인, 이 문장 안에서의 먹었다

즉 Self-Attention 1회는 모든 단어의 표현을 “문맥을 반영한 표현”으로 갱신하는 연산이다.

이것이 왜 중요한가? Ch10에서 임베딩의 한계를 하나 남겨 두었다 — 같은 단어는 늘 같은 벡터라는 것. “강가의 은행에 앉았다”와 “돈을 맡기러 은행에 갔다”에서 “은행”은 전혀 다른 뜻이지만, 임베딩 사전에는 “은행” 벡터가 하나뿐이다. Self-Attention을 통과하면 첫 문장의 “은행”은 “강가”의 Value를 많이 섞고, 둘째 문장의 “은행”은 “돈”과 “맡기러”의 Value를 많이 섞는다 — 같은 단어가 문장마다 다른 벡터가 된다. 다의어 문제가 구조적으로 풀리는 것이다.

인과 마스크: 미래를 보면 안 된다

지금까지의 계산에는 문제가 하나 있다. “고양이가”의 새 표현을 만들 때 뒤에 오는 “먹었다”를 참고했다. 문장 전체를 이해하는 작업(분류, 번역의 입력 쪽)에서는 문제가 없지만, 다음 단어를 맞히는 작업에서는 치명적이다.

“나는 어제 학교에 ___” 의 빈칸을 맞히는데 정답을 미리 보여준다면? 모델은 아무것도 배우지 않고 정답을 베낀다. 학습은 완벽해 보이지만 실전에서는 무용지물이다.

정의: 인과 마스크 (Causal Mask)

각 토큰이 자기 자신과 그 이전 토큰만 참고하도록, 스코어 표의 오른쪽 위 삼각형을 \(-\infty\) 로 만드는 것. Softmax를 통과하면 \(e^{-\infty} = 0\) 이 되어 가중치가 정확히 0이 된다.

손계산: 마스크를 씌우면 어떻게 달라지는가

앞의 스케일링된 스코어에 마스크를 씌운다. 회색이 가려지는 칸이다.

\[ \begin{array}{c|ccc} & \text{고양이가} & \text{생선을} & \text{먹었다} \\ \hline \text{고양이가} & 1.41 & \color{gray}{-\infty} & \color{gray}{-\infty} \\ \text{생선을} & 0.71 & 2.83 & \color{gray}{-\infty} \\ \text{먹었다} & 0.71 & 4.24 & 2.83 \end{array} \]

이제 행마다 살아남은 칸끼리만 Softmax를 한다.

1행 (고양이가) — 볼 수 있는 것이 자기 하나뿐이다.

\[\text{softmax}(1.41) = 1.000\]

2행 (생선을) — 두 칸만 남았다.

\[e^{0.71} = 2.028, \quad e^{2.83} = 16.919, \quad \text{합} = 18.947\] \[\left(\frac{2.028}{18.947},\ \frac{16.919}{18.947}\right) = (0.107,\ 0.893)\]

3행 (먹었다) — 가릴 것이 없으므로 앞의 계산과 같다: \((0.023,\ 0.786,\ 0.191)\)

Query \ Key 고양이가 생선을 먹었다
고양이가 1.000 — —
생선을 0.107 0.893 —
먹었다 0.023 0.786 0.191

아래쪽 삼각형만 남았다. 각 행의 합은 여전히 1이다.

코드 
import numpy as np
import pandas as pd

Q = np.array([[2, 1], [1, 2], [1, 3]], dtype=float)
K = np.array([[1, 0], [0, 2], [1, 1]], dtype=float)
V = np.array([[1, 0], [0, 1], [1, 1]], dtype=float)
tokens = ['고양이가', '생선을', '먹었다']

def attn(S):
    e = np.exp(S - S.max(axis=1, keepdims=True))
    W = e / e.sum(axis=1, keepdims=True)
    return W, W @ V

S = (Q @ K.T) / np.sqrt(2)
W_free, out_free = attn(S)

mask = np.triu(np.ones((3, 3)), k=1).astype(bool)   # 오른쪽 위 삼각형
S_masked = S.copy(); S_masked[mask] = -np.inf
W_causal, out_causal = attn(S_masked)

pd.DataFrame({
    '토큰': tokens,
    '마스크 없음': [f'({v[0]:.3f}, {v[1]:.3f})' for v in out_free],
    '인과 마스크': [f'({v[0]:.3f}, {v[1]:.3f})' for v in out_causal],
}).to_html(index=False, border=0)

“고양이가”의 표현이 크게 달라졌다 — 마스크가 없을 때는 뒤 단어들의 정보가 섞였지만, 이제는 자기 자신의 Value \((1, 0)\) 그대로다. 아직 아무 문맥도 없는 문장의 첫 단어이니 당연하다. 반대로 마지막 토큰 “먹었다”는 볼 수 있는 것이 원래부터 전부였으므로 변화가 없다.

두 종류의 어텐션. 마스크 없는 것을 양방향(bidirectional), 마스크 있는 것을 인과(causal) 어텐션이라 한다. BERT 계열은 전자, GPT 계열은 후자를 쓴다. 이 수업에서 다루는 언어모델(Ch12)은 다음 토큰을 맞히므로 인과 어텐션이다.

Multi-Head Attention: 관점을 여러 개 두기

왜 하나로는 부족한가

지금까지 계산한 어텐션은 관점 하나다. 그런데 “먹었다”가 알아야 할 것은 하나가 아니다.

  • 무엇을 먹었나 → “생선을”을 봐야 한다
  • 누가 먹었나 → “고양이가”를 봐야 한다
  • 언제인가 → 시제를 나타내는 토큰을 봐야 한다

가중치 행 하나로는 이 셋을 동시에 표현할 수 없다. 합이 1이라 한 곳을 보면 다른 곳을 못 본다. 해법은 단순하다 — 어텐션을 여러 벌 병렬로 돌리고 결과를 합친다.

정의: Multi-Head Attention

\(d_{\text{model}}\) 차원을 \(h\) 개의 head로 나누어 각각 독립적으로 어텐션을 수행한 뒤, 결과를 이어 붙이고(concat) 마지막에 행렬 \(W_O\) 를 한 번 곱하는 구조.

\[d_{\text{head}} = \frac{d_{\text{model}}}{h}\]

텐서 모양 따라가기 — 이것이 전부다

\(d_{\text{model}} = 4\), head 2개, 토큰 3개인 경우를 모양만 좇아가 보자. 계산 내용은 앞에서 손으로 한 것과 똑같다.

단계 연산 모양
① 입력 임베딩 \(X\) \((3,\ 4)\)
② 투영 \(XW_Q,\ XW_K,\ XW_V\) 각 \((3,\ 4)\)
③ 분할 마지막 축을 head 2개로 쪼갠다 각 head가 \((3,\ 2)\)
④ 어텐션 head마다 따로 — 앞 절의 계산 그대로 각 head 출력 \((3,\ 2)\)
⑤ 결합 두 결과를 옆으로 이어 붙인다 (concat) \((3,\ 4)\)
⑥ 투영 \(W_O\) 를 곱해 섞는다 \((3,\ 4)\)
들어간 모양과 나온 모양이 같다

\((3, 4)\) 로 들어가서 \((3, 4)\) 로 나온다. 이것이 결정적이다 — 모양이 보존되므로 같은 블록을 몇 번이고 쌓을 수 있다. Ch12에서 이 블록을 12층, 96층 쌓게 되는 근거가 여기에 있다.

그리고 우리가 손으로 계산한 \(d=2\) 짜리 어텐션이 바로 head 하나였다. Multi-Head는 그것을 여러 번 하고 붙이는 것뿐이다 — 새 수학은 여기서도 없다.

코드 
rows = [
    ('① 입력 X',              '(3, 4)'),
    ('② Q = X @ W_Q',         '(3, 4)'),
    ('③ head 분할 → head 1',  '(3, 2)'),
    ('③ head 분할 → head 2',  '(3, 2)'),
    ('④ head 1 어텐션 출력',  '(3, 2)'),
    ('④ head 2 어텐션 출력',  '(3, 2)'),
    ('⑤ concat',              '(3, 4)'),
    ('⑥ @ W_O',               '(3, 4)'),
]

파라미터 수 세기

Multi-Head Attention이 가진 학습 파라미터는 행렬 네 개뿐이다. head를 몇 개로 쪼개든 총 파라미터 수는 변하지 않는다 — 쪼개기만 할 뿐이기 때문이다.

\[W_Q,\ W_K,\ W_V,\ W_O \;:\; \text{각각 } d_{\text{model}} \times d_{\text{model}}\]

\[\boxed{\text{파라미터 수} = 4 \times d_{\text{model}}^2}\]

\(d_{\text{model}}\) head 수 \(d_{\text{head}}\) 파라미터 수
4 2 2 \(4 \times 16 = 64\)
768 (BERT-base) 12 64 \(4 \times 768^2 = 2{,}359{,}296\)
768 8 96 같은 2,359,296

마지막 두 줄을 비교하라. head를 12개로 쪼개든 8개로 쪼개든 파라미터 수는 같다. head 수는 “몇 개의 관점으로 나눌 것인가”를 정하는 하이퍼파라미터(Ch01)일 뿐이다.

편향까지 포함하면 \(4d_{\text{model}}^2 + 4d_{\text{model}}\) 이지만, 파라미터 수를 어림할 때는 제곱항이 지배적이라 흔히 \(4d^2\) 으로 센다. 문제집에서는 편향 포함 여부를 문제에 명시한다.

왜 혁명이었나

2017년 논문 “Attention Is All You Need”가 제안한 이 구조는 몇 년 만에 자연어 처리 전체를 갈아치웠다. 이유는 성능만이 아니다 — 확장성이다.

RNN Transformer
처리 방식 한 단어씩 순차 처리 모든 단어 동시 처리
단어 1,000개 문장 1,000단계 대기 행렬 곱 몇 번 (병렬)
먼 단어 참조 기억 상자를 거쳐 간접적으로 어텐션으로 직접 (거리 무관)
GPU 활용 구조적으로 제한 완전 활용 가능

스코어 계산이 결국 행렬 곱 \(QK^\top\) 하나라는 점을 상기하자. 행렬 곱은 GPU가 가장 잘하는 연산이다(Ch01). “순서대로 기다려야 하는” 구조가 사라지자, 데이터를 더 붓고 모델을 더 키우면 성능이 계속 오르는 시대가 열렸다 — 더 큰 모델, 더 많은 데이터, 더 많은 GPU의 스케일 경쟁이 시작된 것이다.

그런데 아직 Transformer를 만든 것은 아니다. 우리가 가진 것은 부품 하나 — Multi-Head Self-Attention이다. 여기에 세 가지가 더 필요하다.

  • 순서: 모든 단어를 동시에 보는 순간 “몇 번째 단어인가”가 사라졌다. 어디에도 위치 정보가 없다
  • 깊이: 블록을 수십 개 쌓으려면 Ch04의 기울기 소실을 넘어야 한다
  • 변환: 어텐션은 정보를 섞기만 한다 — 각 위치에서 가공하는 층이 따로 필요하다

이 셋을 채워 블록 하나를 완성하고, 그것을 쌓아 언어모델을 만드는 것이 다음 장이다.

깊이 계약 확인

문제집과 시험이 다루는 것은 세 가지다.

  1. 어텐션 손계산 1회 — “내적 → \(\sqrt{d}\) 나누기 → Softmax → 가중합”. Q·K·V는 항상 주어진다
  2. 인과 마스크를 적용한 가중치 계산 — 가린 뒤 남은 칸끼리만 Softmax
  3. Multi-Head의 모양 추적과 파라미터 수 — \(d_{\text{head}} = d_{\text{model}}/h\), 파라미터 \(4d_{\text{model}}^2\)

범위 밖: 어텐션의 역전파 유도, \(W_Q, W_K, W_V\) 를 임베딩에서 만드는 과정의 수치 계산, encoder-decoder 구조. 위치 인코딩과 LayerNorm은 다음 장에서 다룬다.

핵심 요약

개념 핵심 내용
RNN의 병목 순차 처리(병렬 불가) + 먼 기억 소실 — 뿌리는 “순서대로, 기억 상자 하나”
어텐션 유사도(내적, Ch10) → 가중치(Softmax, Ch03) → 가중평균. 새 수학 없음
Q / K / V 찾는 것 / 색인 / 전달할 내용 — 임베딩 × 학습 행렬 \(W_Q, W_K, W_V\)
스케일링 스코어를 \(\sqrt{d}\)로 나눔 — Softmax의 극단화 완화
Self-Attention 문장이 스스로를 참조 → 모든 단어가 “문맥을 반영한 표현”으로 갱신
인과 마스크 오른쪽 위 삼각형을 \(-\infty\) → 미래를 못 보게 막는다. GPT 계열이 쓰는 방식
Multi-Head \(d_{\text{model}}\) 을 head로 쪼개 병렬 어텐션 → concat → \(W_O\). 모양이 보존된다
