컴퓨터 비전과 이미지 데이터

학습 목표
  • 컴퓨터 비전(Computer Vision)이 무엇이며, 어떤 분야에 활용되는지 설명할 수 있다
  • 컴퓨터가 이미지를 숫자 행렬(픽셀)로 표현하는 원리를 이해한다
  • 흑백 이미지와 컬러(RGB) 이미지의 데이터 구조 차이를 설명할 수 있다
  • 완전연결 신경망(FC NN)으로 이미지를 처리할 때의 한계를 이해한다
  • 이미지를 신경망에 넣기 전 리사이즈와 정규화가 왜 필요한지 설명하고 직접 계산할 수 있다
  • 이미지 인식에서 특성 추출(Feature Extraction)이 왜 핵심인지 설명할 수 있다

컴퓨터 비전이란?

이미지에서 정보를 읽다

앞 장들에서 우리는 수치 데이터를 입력으로 받는 신경망을 배웠다. 그런데 현실 세계의 데이터는 숫자만 있는 것이 아니다 — 사진, 영상, 의료 이미지 등 시각 정보가 넘쳐난다.

정의: 컴퓨터 비전 (Computer Vision)

이미지로부터 유용한 정보를 추출하여 의사결정 및 예측에 사용하는 분야. 사람이 눈으로 수행하던 시각적 판단 작업을 컴퓨터가 자동으로 대체할 수 있게 한다.

컴퓨터 비전의 응용

컴퓨터 비전은 이미 우리 생활 곳곳에서 활용되고 있다.

분야 설명 예시
안면 인식 얼굴의 특징점을 추출하여 신원 확인 보안 시스템, 스마트폰 잠금 해제
질병 진단 X-ray, CT 등 의료 이미지 분석 유방암 검출, 피부암 분류, COVID-19 진단
자율 주행 실시간 영상에서 차량·보행자·차선 인식 테슬라 오토파일럿
품질 검사 제조 공정에서 불량품 자동 검출 부품 표면 결함 탐지

이 모든 응용의 공통점은 “이미지를 입력으로 받아 판단을 출력한다”는 것이다. 그렇다면 컴퓨터는 이미지를 어떻게 “이해”할까?

컴퓨터가 보는 이미지

픽셀: 이미지의 기본 단위

사람의 눈에 이미지는 연속적인 색과 형태로 보이지만, 컴퓨터에게 이미지는 밝기가 다른 격자(grid)의 모음이다.

정의: 픽셀 (Pixel)

이미지를 구성하는 최소 단위. 각 픽셀은 하나의 밝기 값(숫자)을 가진다.

  • 흑백(Grayscale): 0(검은색) ~ 255(흰색) 사이의 정수
  • 이미지 전체는 픽셀값으로 이루어진 2차원 행렬로 표현된다

왜 하필 255인가? 픽셀 하나를 1바이트(8비트)로 저장하기 때문이다. 8비트로 표현 가능한 경우의 수가 \(2^8 = 256\) 가지이므로, \(0\)부터 \(255\)까지가 된다.

예를 들어, \(18 \times 12\) 크기의 흑백 이미지는 \(18 \times 12 = 216\)개의 숫자로 표현된다. 아래는 감을 잡기 위한 \(8 \times 8\) 축소 예시다 — 64개의 숫자가 모여 “어두운 원” 무늬 하나를 이룬다.

gray_rows = 8
gray_cols = 8
gray_img_raw = [
  [220, 210, 180, 120,  80, 120, 180, 210],
  [210, 180, 100,  40,  20,  40, 100, 180],
  [180, 100,  30,  10,   5,  10,  30, 100],
  [150,  60,  10,   0,   0,   0,  10,  60],
  [150,  60,  10,   0,   0,   0,  10,  60],
  [180, 100,  30,  10,   5,  10,  30, 100],
  [210, 180, 100,  40,  20,  40, 100, 180],
  [220, 210, 180, 120,  80, 120, 180, 210]
]
gray_pixels = {
  const arr = [];
  for (let r = 0; r < 8; r++)
    for (let c = 0; c < 8; c++)
      arr.push({row: r, col: c, val: gray_img_raw[r][c]});
  return arr;
}
인터랙티브 — 픽셀 위에 마우스를 올려 밝기값을 확인해 보세요

각 셀의 색은 픽셀값(0~255)에 대응합니다. 0에 가까울수록 어둡고, 255에 가까울수록 밝습니다.

viewof hoveredPixel = {

      d3.select(this).attr("stroke", "#ccc").attr("stroke-width", 1);

    })
    .on("click", function(event, d) {
      svg.selectAll("rect").attr("stroke", "#ccc").attr("stroke-width", 1);
      d3.select(this).attr("stroke", "#8C1515").attr("stroke-width", 2.5);
      tooltip.text(`위치 [${d.row}, ${d.col}]  →  픽셀값 = ${d.val}`);
    });

  svg.selectAll(".lbl")
    .data(gray_pixels)
    .join("text")
    .attr("class", "lbl")
    .attr("x", d => pad + d.col * (size + pad) + size / 2)
    .attr("y", d => pad + d.row * (size + pad) + size / 2 + 4)
    .attr("text-anchor", "middle")
    .attr("font-size", "11px")
    .attr("fill", d => d.val > 128 ? "#333" : "#ddd")
    .attr("pointer-events", "none")
    .text(d => d.val);

  return svg.node();
}

컬러 이미지: RGB 3채널

흑백 이미지가 2차원 행렬이라면, 컬러 이미지는 어떻게 표현할까?

모든 색깔은 빨강(R), 초록(G), 파랑(B) 세 가지 빛의 조합으로 만들 수 있다. 따라서 컬러 이미지는 3개의 2차원 행렬을 쌓은 3차원 텐서로 표현된다.

\[\text{컬러 이미지} \in \mathbb{R}^{H \times W \times 3}\]

  • \(H\): 세로 픽셀 수 (높이)
  • \(W\): 가로 픽셀 수 (너비)
  • \(3\): R, G, B 채널

viewof rgbChannel = Inputs.radio(["RGB (합성)", "R (빨강)", "G (초록)", "B (파랑)"], {value: "RGB (합성)", label: "채널 선택"})
{
  const size = 56;
  const pad = 2;

    .attr("viewBox", `0 0 ${W} ${H}`)

이미지 유형 데이터 형태 예시 (28×28)
흑백 \(H \times W\) \(28 \times 28 = 784\)개 숫자
컬러 \(H \times W \times 3\) \(28 \times 28 \times 3 = 2{,}352\)개 숫자

잠깐 — “텐서”란?

앞에서 컬러 이미지를 “3차원 텐서”라고 불렀다. 겁먹을 필요 없는 말이다.

정의: 텐서 (Tensor)

숫자를 담는 상자를, 축(axis)이 몇 개인지로 부르는 이름.

축의 수 이름 예
0 스칼라 (Scalar) 온도 \(27.2\)
1 벡터 (Vector) 한 사람의 특성 \([34,\; 52000,\; 3]\)
2 행렬 (Matrix) Ch01의 정형 데이터 표 \((n \times p)\), 흑백 이미지 \((H \times W)\)
3 3차원 텐서 컬러 이미지 \((H \times W \times 3)\)
4 4차원 텐서 컬러 이미지 배치 \((B \times H \times W \times 3)\)

Ch04에서 배운 배치(batch) 를 떠올리자. 이미지를 32장씩 묶어 넣으면 축이 하나 더 붙어 \(32 \times 224 \times 224 \times 3\) 이 된다. 딥러닝의 데이터는 대부분 4차원 텐서다.

채널 축의 위치가 도구마다 다르다. 이 교재와 대부분의 그림은 \((H, W, C)\) 순서로 쓰지만, PyTorch는 \((C, H, W)\) 순서를 쓴다. 실습에서 “채널이 3인데 왜 에러가 나지?” 하는 상황의 절반은 이 순서 때문이다. 텐서를 다룰 때는 항상 shape을 먼저 찍어 보는 습관을 들이자.

신경망에 넣기 전 — 리사이즈와 정규화

이미지가 숫자 행렬이라는 것은 알았다. 그런데 그 숫자를 그대로 신경망에 넣으면 안 된다. 두 가지를 먼저 손봐야 한다.

문제 1 — 크기가 제각각이다

스마트폰으로 찍은 사진은 보통 \(4032 \times 3024\) 다. 그런데 신경망의 입력층은 노드 수가 고정되어 있다 (Ch01의 \(p\) 를 떠올리자). 사진마다 크기가 다르면 넣을 수가 없다.

리사이즈 (Resize)

모든 이미지를 같은 크기로 통일하는 것. 흔히 \(224 \times 224\) 나 \(128 \times 128\) 을 쓴다.

  • Resize: 이미지 전체를 목표 크기로 늘리거나 줄인다 (가로세로 비율이 깨질 수 있다)
  • Center Crop: 가운데를 정사각형으로 잘라낸 뒤 줄인다 (비율은 지키되 가장자리가 잘린다)

\(4032 \times 3024\) 를 \(224 \times 224\) 로 줄이면 픽셀 수가 \(12{,}192{,}768 \to 50{,}176\) 으로 약 243배 줄어든다. 정보를 버리는 것 같지만, 대부분의 분류 과제에서는 이 정도로 충분하다 — 오히려 원본 그대로는 학습이 불가능할 만큼 무겁다.

직접 촬영할 때의 함의: 어차피 \(224 \times 224\) 로 줄어들 것이므로, 대상이 화면에서 너무 작게 찍히면 줄인 뒤에는 몇 픽셀 남지 않는다. 대상이 프레임을 적당히 채우도록 찍어야 한다.

문제 2 — 값의 범위가 신경망에 부적합하다

픽셀값은 \(0 \sim 255\) 다. Ch04에서 배웠듯이 입력 스케일이 크면 학습이 불안정해진다. 그래서 \(255\) 로 나누어 \(0 \sim 1\) 범위로 만든다.

\[x' = \frac{x}{255}\]

이것이 바로 Ch04에서 예고했던 Min-Max 정규화다. \(x' = \dfrac{x - x_{\min}}{x_{\max} - x_{\min}} = \dfrac{x - 0}{255 - 0} = \dfrac{x}{255}\) — 이미지는 최솟값 0, 최댓값 255가 이미 정해져 있으므로 나누기만 하면 된다. 정형 데이터처럼 훈련 데이터에서 평균·표준편차를 구할 필요가 없다.

✍️ 손으로 따라 계산하기 — 전처리 파이프라인

\(3000 \times 2000\) 컬러 사진 한 장을 \(224 \times 224\) 로 리사이즈하고 정규화한다.

단계 1 — 원본의 숫자 개수.

\[3000 \times 2000 \times 3 = 18{,}000{,}000 \text{ 개}\]

단계 2 — 리사이즈 후.

\[224 \times 224 \times 3 = 150{,}528 \text{ 개} \quad (\text{약 } 120\text{배 감소})\]

단계 3 — 정규화. 어떤 픽셀의 R값이 \(200\) 이었다면:

\[200 \div 255 = 0.784\]

단계 4 — 최종 텐서의 모양. 이 사진 32장을 배치로 묶으면:

\[32 \times 224 \times 224 \times 3 \quad (\text{PyTorch에서는 } 32 \times 3 \times 224 \times 224)\]

✍️ 직접 해보기

\(1920 \times 1080\) 흑백 이미지를 \(128 \times 128\) 로 리사이즈했다. ① 리사이즈 후 숫자 개수, ② 픽셀값 \(51\) 의 정규화 값을 구하라.

정답 펼치기

① 흑백이므로 채널이 1이다: \(128 \times 128 \times 1 = \mathbf{16{,}384}\) 개 (원본은 \(1920 \times 1080 = 2{,}073{,}600\) 개였으므로 약 127배 감소)

② \(51 \div 255 = \mathbf{0.2}\)

사전 학습 모델을 쓸 때는 정규화 규칙이 하나 더 붙는다. 남이 학습해 둔 모델을 가져다 쓰려면, 그 모델이 학습할 때 사용한 것과 똑같은 전처리를 해야 한다. Ch08 전이학습에서 다시 다룬다.

완전연결 신경망의 한계

이미지를 FC 신경망에 넣으려면?

Ch02~Ch03에서 배운 완전연결(Fully Connected) 신경망에 이미지를 입력하려면, 2차원 행렬을 1차원 벡터로 펼쳐야(flatten) 한다.

\(18 \times 12\) 흑백 이미지의 경우 입력 노드가 216개이므로 관리할 만하다. 하지만 실제 이미지는 어떨까?

파라미터 폭발 문제

✍️ 손으로 따라 계산하기 — 첫 층에서만 몇 개인가

\(224 \times 224\) 컬러 이미지를 FC 신경망의 은닉층 \(256\)개 노드에 연결한다. 첫 번째 층의 가중치는 몇 개인가?

단계 1 — 펼친 입력 노드 수. 컬러이므로 채널 3을 빠뜨리면 안 된다.

\[224 \times 224 \times 3 = 150{,}528\]

단계 2 — 가중치 수. Ch02의 공식 \(n_{l-1} \times n_l\) 그대로다.

\[150{,}528 \times 256 = 38{,}535{,}168\]

단계 3 — 편향을 더한다. 출력 노드 하나당 하나:

\[38{,}535{,}168 + 256 = \mathbf{38{,}535{,}424} \;\approx\; 3{,}850\text{만 개}\]

이것이 첫 번째 층 하나의 값이다. 뒤에 층을 더 쌓으면 계속 늘어난다.

✍️ 직접 해보기

\(64 \times 64\) 흑백 이미지를 은닉 \(128\) 노드에 연결하면 첫 층의 파라미터는 몇 개인가?

정답 펼치기

입력 노드 \(= 64 \times 64 \times 1 = 4{,}096\)

파라미터 \(= 4{,}096 \times 128 + 128 = 524{,}288 + 128 = \mathbf{524{,}416}\) 개

64×64 흑백이라는 아주 작은 이미지인데도 52만 개다.

인터랙티브 — 이미지 크기에 따른 FC 파라미터 수를 확인해 보세요

이미지 크기와 은닉 뉴런 수를 조절하면 첫 번째 FC 층의 가중치 수가 어떻게 변하는지 확인할 수 있습니다.

viewof imgPreset = Inputs.radio(

  {value: "중간 컬러 (224×224)", label: "이미지 크기"}

    .attr("font-size", "12").attr("fill", "#555").text(`= ${fmt(inputSize)}개 노드`);

  // Arrow
  svg.append("text").attr("x", 185).attr("y", 73).attr("font-size", "16").attr("fill", "#555").text("→");

  // Multiply box
  svg.append("rect").attr("x", 210).attr("y", 30).attr("width", 140).attr("height", 80).attr("rx", 8)
    .attr("fill", "#E3F2FD").attr("stroke", "#1565C0").attr("stroke-width", 1.5);

224×224 컬러 이미지만 해도 첫 번째 층의 가중치가 수천만 개에 달한다. 이는 단 하나의 층에 대한 수치이므로, 전체 네트워크의 파라미터는 훨씬 더 많아진다.

FC 접근법의 두 가지 문제

완전연결 신경망으로 이미지를 처리하면 다음 두 가지 근본적인 문제가 발생한다.

문제 설명
공간 정보 손실 2D 행렬을 1D 벡터로 펼치면(flatten), 인접한 픽셀 간의 위치 관계가 사라진다
파라미터 폭발 입력 노드 수가 픽셀 수와 같으므로, 가중치가 픽셀 수에 비례해(이미지 한 변 길이의 제곱으로) 증가한다

224×224×3 이미지를 256개 은닉 뉴런에 연결하면, 첫 번째 층에서만 약 3,800만 개의 가중치가 필요하다. 학습이 불가능한 것은 아니다 — 하지만 Ch04에서 배운 그대로다: 파라미터가 많을수록 암기할 용량이 커지고, 과적합을 막으려면 그만큼 많은 데이터가 필요하다. 이미지 하나를 처리하기 위해 이런 낭비를 감수할 이유가 없다.

공간 정보 손실을 직접 확인하기

두 문제 중 파라미터 폭발은 위의 계산기에서 확인했다. 그렇다면 “공간 정보 손실”은 정확히 무엇이 문제인가?

인터랙티브 — 같은 패턴, 다른 위치

슬라이더로 2×2 밝은 패턴을 좌우로 옮겨 보세요. 이미지에서는 “같은 무늬가 옆으로 이동”했을 뿐인데, 펼쳐진 벡터에서는 전혀 다른 입력 노드가 값을 받습니다.

viewof patPos = Inputs.range([0, 4], { step: 1, label: "패턴의 가로 위치", value: 0 })
{
  const n = 6, size = 34, pad = 2;
  const patIdx = new Set([12 + patPos, 13 + patPos, 18 + patPos, 19 + patPos]);

  const gridW = n * (size + pad) + pad;
  const stripSize = 15, stripPad = 1.5;
  const stripW = 36 * (stripSize + stripPad) + stripPad;
  const W = Math.max(gridW, stripW) + 20, H = gridW + 105;

  const svg = d3.create("svg")
    .attr("viewBox", `0 0 ${W} ${H}`)
    .attr("width", "100%")
    .style("max-width", "660px")
    .style("font-family", "Pretendard, sans-serif");

  // 6x6 grid
  const gx = (W - gridW) / 2;
  for (let r = 0; r < n; r++) {
    for (let c = 0; c < n; c++) {
      const i = r * n + c;
      const on = patIdx.has(i);
      svg.append("rect")
        .attr("x", gx + pad + c * (size + pad))
        .attr("y", pad + r * (size + pad))
        .attr("width", size).attr("height", size).attr("rx", 3)
        .attr("fill", on ? "#D4A017" : "#ECEFF1")
        .attr("stroke", "#ccc").attr("stroke-width", 1);
    }
  }
  svg.append("text").attr("x", W / 2).attr("y", gridW + 20)
    .attr("text-anchor", "middle").attr("font-size", "11").attr("fill", "#555")
    .text("6×6 이미지 — 같은 2×2 패턴이 좌우로 이동할 뿐");

  // flatten arrow
  svg.append("text").attr("x", W / 2).attr("y", gridW + 40)
    .attr("text-anchor", "middle").attr("font-size", "11").attr("fill", "#8C1515")
    .attr("font-weight", "600").text("↓ flatten (한 줄로 펼치기)");

  // 1x36 strip
  const sx = (W - stripW) / 2;
  for (let i = 0; i < 36; i++) {
    const on = patIdx.has(i);
    svg.append("rect")
      .attr("x", sx + stripPad + i * (stripSize + stripPad))
      .attr("y", gridW + 50)
      .attr("width", stripSize).attr("height", stripSize).attr("rx", 2)
      .attr("fill", on ? "#D4A017" : "#ECEFF1")
      .attr("stroke", "#ccc").attr("stroke-width", 0.7);
  }
  const active = [...patIdx].sort((a, b) => a - b).map(i => `#${i + 1}`).join(", ");
  svg.append("text").attr("x", W / 2).attr("y", gridW + 88)
    .attr("text-anchor", "middle").attr("font-size", "12").attr("fill", "#333")
    .text(`값을 받는 입력 노드: ${active}`);

  return svg.node();
}

패턴을 한 칸만 옮겨도 활성 노드 번호가 통째로 바뀐다. FC 신경망에서 각 입력 노드는 자기만의 가중치를 가지므로, 왼쪽 위치에서 “이 무늬는 고양이 귀”라고 학습한 가중치를 오른쪽 위치에 재사용할 수 없다 — 같은 무늬를 위치마다 처음부터 다시 배워야 한다. “위치가 달라도 같은 패턴은 같은 방법으로 찾는다”는 연산이 필요하며, 그것이 다음 장의 콘볼루션이다.

인간의 시각과 특성 추출

사람은 이미지를 어떻게 인식하는가?

사람은 이미지를 볼 때 모든 픽셀을 하나하나 분석하지 않는다. 대신 핵심 특성(Feature)을 찾아 비교하는 방식으로 인식한다.

예를 들어 “사람 얼굴”을 인식할 때, 우리는 무의식적으로 눈, 코, 입이라는 특성을 찾는다. “자동차”라면 바퀴, 헤드램프, 번호판 같은 특성으로 판별한다.

컴퓨터 비전의 핵심 질문

사람의 개입 없이, 자동으로 이미지의 핵심 특성을 추출할 수 있을까?

이것이 바로 컴퓨터 비전이 해결해야 할 근본적인 질문이다. 실제로 딥러닝(특히 CNN)은 이 특성 추출 과정을 자동으로 학습하는데, 추출되는 특성은 계층적 구조를 가진다.

수준 추출되는 특성 예시
Low-level 기본적인 시각 패턴 에지(edge), 밝기 변화, 점
Mid-level 부분적인 구조 눈, 귀, 코 등 부위
High-level 전체적인 형태 얼굴 전체 구조, 자세

이 계층적 특성 추출이 어떻게 가능한지는 다음 장에서 콘볼루션(Convolution) 연산을 통해 알아본다.

특성 추출이 어려운 이유

같은 대상이라도 촬영 조건에 따라 전혀 다른 이미지가 될 수 있다. 컴퓨터가 자동으로 특성을 파악하기 어렵게 만드는 요인들은 다음과 같다.

요인 설명
시점 변화 (Viewpoint) 같은 물체를 다른 각도에서 촬영하면 전혀 다른 모양
크기 변화 (Scale) 물체의 크기가 작거나 크면 픽셀 분포가 달라짐
변형 (Deformation) 고양이가 웅크리거나 뛰는 등 같은 대상의 형태 변화
가려짐 (Occlusion) 물체의 일부가 다른 물체에 가려진 경우
조명 (Illumination) 명암과 그림자에 따라 같은 물체도 다르게 보임
배경 혼잡 (Background) 물체와 배경의 색·질감이 유사하면 구분 곤란
클래스 내 변이 (Intra-class) “의자”라 해도 소파, 안락의자, 접이식 등 생김새가 다양
이 표는 팀 프로젝트의 촬영 체크리스트다

여러분이 프로젝트에서 직접 데이터를 수집할 때, 위 요인들은 남의 이야기가 아니라 여러분 모델의 성패가 된다. 같은 사물을 다양한 시점·거리·조명·배경에서 찍을수록 모델은 이 난관들에 강해진다. 반대로 같은 자리에서 같은 각도로만 찍은 200장은, 사실상 20장짜리 데이터다.

이러한 난관을 극복하기 위해, 단순히 픽셀값을 나열하는 FC 방식이 아닌 이미지의 공간적 구조를 활용하는 새로운 연산이 필요하다.

정리

이 장에서는 컴퓨터 비전의 기본 개념과 이미지 데이터의 구조를 살펴보았다.

핵심 내용 요약
이미지 = 숫자 행렬 흑백은 \(H \times W\), 컬러는 \(H \times W \times 3\)의 텐서
텐서 축의 개수로 부르는 숫자 상자 — 배치까지 넣으면 4차원
리사이즈 크기를 통일해야 입력층에 넣을 수 있다 (보통 224×224)
정규화 픽셀값을 255로 나눠 \(0 \sim 1\) 로 — Ch04의 Min-Max 정규화
FC의 한계 공간 정보 손실 + 파라미터 폭발로 이미지 처리에 부적합
특성 추출이 핵심 사람처럼 핵심 특성을 자동으로 추출하는 방법이 필요
다양한 난관 시점, 크기, 변형, 가려짐 등으로 자동 특성 추출이 어려움

다음 장 예고: 이미지의 공간적 구조를 보존하면서, 적은 파라미터로 효과적인 특성을 추출하는 연산 — 콘볼루션(Convolution)을 배운다.
